## 主稿（约 2'40"）

**【开场 · 0:00–0:20】**

面试官好，我重点讲一下我独立做的「合同审查智能体」这个项目。背景是这样的：法务审一份三十页的合同，光逐条盯违约金、试用期这些硬伤就要半小时以上，而且人眼特别容易漏——比如违约金偷偷写成 35%、试用期写成 8 个月，这种合规红线一不注意就放过去了。但反过来，直接把合同丢给大模型，它又会编法条、编案例，法务根本不敢直接采信。所以我这个项目核心就三句话：**规则闸门先拦确定性的硬伤、RAG 检索给它补真法条依据、最后一道人工门控把住可信关。**

**【模块一 · 规则闸门 + 四维并发 · 0:20–0:55】**

具体落地我分四块讲。第一块是规则闸门。我没有一上来就让 LLM 审，而是先加了一道纯正则的确定性规则拦截——违约金超过 30% 直接标红、试用期超过 6 个月判高风险，毫秒级、零 Token 成本。能靠规则判的事，绝不让大模型重复干。过了闸门之后才是语义审查，这部分我让法律、合规、财务、权责四个维度用 LangGraph 的 Send 并发去评，一份合同四路同时跑。

**【模块二 · 混合检索 + 查询增强（主菜） · 0:55–1:45】**

第二块，也是我觉得最有技术含量的，是检索。合同里用户说的话和法条完全是两套语言——比如用户问「仓库被雷劈了货烧了我要不要赔」，法条写的是「因不可抗力」，纯向量检索基本零召回。我的做法是三层：底层用 BGE-M3 做 dense 加 sparse 混合召回，再加权融合；中间用 BGE-Reranker 交叉编码器精排，只取 Top-15 进上下文；最上层做口语化查询增强——问答侧我加了 HyDE，先让模型生成一段「假设法条文本」再去检索，还做了多查询拆分。效果在我们自己攒的 20 题法律黄金集上，**口语化问题的 Top-3 命中率从 50% 提到了 75%，书面语稳定 100%**。

**【模块三 · HITL 人工门控 · 1:45–2:20】**

第三块是抗幻觉和人工门控。就算检索到了真法条，模型还是可能胡编，所以我特意加了一道「硬门控」：在检索之后、生成修订建议之前，用 LangGraph 的 interrupt 把流水线真暂停，把高风险项推到前端让法务确认、降级或者忽略，确认之后用 Command.resume 再恢复往下走。另外我还接了北大法宝的 MCP，给高风险条款自动补带真实案号的司法判例，专门对抗编案例；它如果挂了就静默降级，不影响主流程。

**【模块四 · 工程兜底 + 数据安全 · 2:20–2:35】**

第四块是工程可靠性和数据安全。parse、review、retrieve、revise 每个节点我都设计了降级路径——解析挂了退回正则切分、检索挂了标记人工核实、修订挂了生成「需人工起草」占位，统一套「重试到降级到系统兜底」三层保护。安全上我主动补了多租户越权校验，用 JWT 解析身份，把十个核心接口的所有权校验都接上，防止用户 A 读到用户 B 的合同。

**【收尾 · 2:35–2:40】**

整体上说，这个项目的检索是有可量化提升的，口语化命中率 50% 到 75%；架构上规则闸门、四维并发、人工门控、全链路降级都是真正落地、有单测和评测脚本覆盖的，不是 demo。

## 1 分钟精简版（应对「只用一句话 / 一分钟讲清楚」）

我独立做了一个合同审查 Agent。痛点有两个：人审合同慢还容易漏合规红线，纯大模型又会编法条法务不敢信。我的做法是三道防线——先用 40 条正则规则零成本拦掉违约金超标、试用期违规这类确定性硬伤；再用 BGE-M3 混合检索加 Reranker 精排加 HyDE 查询增强，把口语化法条召回从 50% 拉到 75%；最后用 LangGraph interrupt 做人工硬门控，高风险项必须法务确认才出修订，还接了北大法宝 MCP 补真实判例抗幻觉。整条流水线六节点全链路可降级，有单测和评测脚本覆盖。

## 提醒（面试前自测）

- 说完主稿后，面试官大概率从「模块二检索」或「模块三 interrupt 怎么恢复」切入深挖，对应弹药见 `简历_合同审查项目经历_最终版.md` 第四节。
- 数字别脱口而出就停，准备好口径：50%→75% 是口语化子集的 recall@3，非全量平均。
- 若被问「为什么不是多 Agent 而是 6 节点」，回：合同审查是单业务流水线，StateGraph 六节点比拆多 Agent 更可控、状态更清晰（review 内部用 Send 并发即可）。
